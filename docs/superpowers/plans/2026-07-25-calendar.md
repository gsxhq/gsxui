# calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `calendar` — a react-day-picker equivalent with single/range/multiple selection, a real keyboard grid, and a correct month rendered before any JavaScript runs.

**Architecture:** Go renders a fixed 6-row, 42-cell grid; JavaScript never creates or destroys a cell, only updates `textContent` and `data-*` in place. That keeps every class string in `calendar.gsx` (styled through data-attribute variants) and confines the Go/JS duplication to one pure function — `monthGrid(year, month, weekStartsOn) → 42 dates`.

**Tech Stack:** gsx (Go server-rendered templating), Tailwind v4, vanilla ES modules through `ui/gsxui.js`'s delegation core, Playwright over the `jstest` harness.

**Source spec:** `docs/superpowers/specs/2026-07-25-calendar-design.md`

**Branch:** `tier4-calendar`. Do not merge to `main`; do not push unless told.

## Global Constraints

- **Markup reference** `registry/new-york-v4/ui/calendar.tsx`; **visual reference** `registry/styles/style-nova.css`; nova wins on disagreement. Never port from `registry/bases/*` — those emit `.cn-*` named classes instead of inline utilities.
- Class carryover is token-for-token. Every drop or deviation is ledgered in `docs/jsx-parity.md`.
- **JavaScript sets no classes.** It sets `data-*`, `textContent`, `tabindex`, `aria-selected`, `aria-label` and `disabled`. All styling is data-attribute variants in `calendar.gsx`.
- **JavaScript never creates or destroys a day cell.** All 42 exist from first paint.
- **All date arithmetic is UTC**, on both sides. Local-midnight arithmetic produces off-by-one-day bugs.
- **Hook attributes are namespaced `data-gsxui-calendar-*`.** `ui/gsxui.js` dispatches to every handler whose selector matches regardless of module; a shared prefix silently runs two components' handlers on one event. `jstest/specs/invariants.spec.ts` enforces this.
- **Behavior registers through `on()` from `./gsxui.js`.** No raw `document.addEventListener`, no `MutationObserver`, no init scan.
- **State is a server-rendered parameter reflected into the DOM; changes emit `gsxui:change`.** The component never chooses a persistence mechanism.
- A dependency existing only in a JS import is invisible to `registry.Deps` and forbidden. `calendar`'s deps are `button`, `icon`, `native-select`, all Go-level imports.
- **Never start or kill processes outside the test rig.** A `gsx dev` server on port 7777 and a Vite server on port 5173 may be running and belong to the user. Playwright's own `webServer` on 127.0.0.1:7799 is the sanctioned exception.
- Any `site/examples/**` change requires `make highlight` in the same commit. Any `.gsx` change requires `go tool gsx generate` and the regenerated `.x.go` in the same commit.
- `make check` must pass end to end: Go suite, Playwright suite, generated-file drift, `node --check`, gofmt.

```

ui/calendar.js           the JS monthGrid twin, navigation, selection, keyboard

site/examples/calendar.go       example registrations
docs/superpowers/plans/2026-07-25-calendar-source-map.md   Task 0's output
```

`monthGrid` lives inside `ui/calendar.gsx` as a plain Go function, the way
`ui/button.gsx` holds `variantClass`/`sizeClass`. It cannot live in a
separate `.go` file: `internal/registry` defines a component as
`ui/<name>.gsx` plus an optional `ui/<name>.js`, so a third file would never
be vendored by `gsxui add calendar`.

**No byte-pinned full render for calendar.** Every other component's tests
pin an exact output string, but a 42-cell grid pin is unreadable and would
churn on every class-token change. `ui/calendar_test.go` asserts the
structural contract instead — cell count, the `data-date` sequence, marker
placement, ARIA wiring. Class strings are covered by the source map and by
targeted `strings.Contains` checks.

**The DOM contract.** Corrected against Task 0's source map §5 and §8 — upstream renders a **real `<table>`**, so row and column-header roles are implicit and must not be written explicitly:

```
root      <div> data-slot="calendar" data-gsxui-calendar
          data-gsxui-calendar-month="2026-07"
          data-gsxui-calendar-mode="single|range|multiple"
          data-gsxui-calendar-week-start="0".."6"
grid      <table> data-gsxui-calendar-grid role="grid"
          aria-multiselectable="true" in range and multiple modes only
header    <thead aria-hidden="true"><tr>
weekday   <th scope="col">Su</th>      NO role="columnheader" — implicit
week row  <tr>                          NO role="row" — implicit
cell      <td role="gridcell" class="group/day"
              data-date="2026-06-28"    ISO, always present
              data-outside              outside the displayed month
              data-today
              data-disabled
              data-focused
              data-selected
              aria-selected="false"
day       <button type="button" data-gsxui-calendar-day
              tabindex="0" on exactly one day, "-1" on the rest
              aria-label="Sunday, June 28, 2026">
```

Three consequences worth stating, all from source map §8:

**Two distinct data-attribute sets, on two elements.** The cell carries the
state the `today`/`outside`/`disabled` class slots style; the button carries
shadcn's own `data-selected-single` / `data-range-start` / `data-range-middle`
/ `data-range-end`, which drive `CalendarDayButton`'s pill colouring. Do not
collapse them onto one element: the `group/day` ring hookup reads the
**cell's** `data-focused` via `group-data-[focused=true]/day:`, and the
button's range-pill colours read the **button's** own attributes. Source map
§3 and §4 have both sets verbatim.

Upstream's button also sets a `data-day` holding a *locale-formatted* string,
colliding by name with the cell's ISO `data-day`. We avoid the collision:
the cell's ISO value is `data-date`, and we do not port the button's
`data-day`.

**Emit the cell's attributes in the order listed above**, `data-date` first.
Several tests assert on adjacent pairs like `data-date="…" data-outside`,
which is only stable if the order is fixed.

**`aria-hidden` on the weekday header is deliberate, not an oversight.**
Reproduce it. It is safe only because every day's `aria-label` already begins
with the weekday name — so the label format is load-bearing, not cosmetic.
`"Sunday, June 28, 2026"`, Go layout `"Monday, January 2, 2006"`. Hiding the
header without that label would lose information; with it, an exposed header
row would just add "column 3, Tuesday" chatter to every arrow-key move.

In `ui/calendar.gsx`, above the component:

```go
// monthGrid returns the 42 dates of the six-week grid that displays the
// given month: seven columns starting at weekStartsOn, six rows, beginning
// at the week start on or before the 1st.
//
// Six rows always, never four or five. react-day-picker sizes the grid to
// the month and changes height between them; a fixed cell count is what lets
// calendar.js update days in place instead of rebuilding the grid, which in
// turn is what keeps every class string in this file and preserves focus
// across navigation. Ledgered as a deviation in docs/jsx-parity.md.
//
// UTC throughout. Local-midnight arithmetic crosses DST boundaries and
// produces off-by-one-day grids twice a year.
//
// This function has a twin in calendar.js. They must agree; the agreement is
// tested in jstest/specs/calendar.spec.ts.
func monthGrid(year int, month time.Month, weekStartsOn time.Weekday) [42]time.Time {
	first := time.Date(year, month, 1, 0, 0, 0, 0, time.UTC)
	offset := (int(first.Weekday()) - int(weekStartsOn) + 7) % 7
	start := first.AddDate(0, 0, -offset)

	var grid [42]time.Time
	for i := range grid {
		grid[i] = start.AddDate(0, 0, i)
	}
	return grid
}
```

```go
// cellFor returns the <td>…</td> substring for the given ISO date, so a test
// can assert on both the cell's own state attributes and the day button
// nested inside it.
func cellFor(t *testing.T, html, isoDate string) string {
	t.Helper()
	anchor := `data-date="` + isoDate + `"`
	i := strings.Index(html, anchor)
	if i < 0 {
		t.Fatalf("no cell for %s", isoDate)
	}
	start := strings.LastIndex(html[:i], "<td")
	if start < 0 {
		t.Fatalf("cell for %s has no opening <td", isoDate)
	}
	end := strings.Index(html[start:], "</td>")
	if end < 0 {
		t.Fatalf("cell for %s has no closing </td>", isoDate)
	}
	return html[start : start+end+len("</td>")]
}
```

```js
// Calendar behavior: month navigation with in-place cell updates.
//
// The 42 day cells are rendered by calendar.gsx and never recreated — this
// module only writes textContent and data-* on cells that already exist.
// That is what keeps every class string in the .gsx (Tailwind scans .gsx and
// .js both, so this is not a styling constraint — it is a single-authority
// one) and what preserves focus across navigation.
import { on, emit } from "./gsxui.js";

const ROOT = "[data-gsxui-calendar]";

// monthGrid is the twin of calendar.gsx's monthGrid. Same contract: 42 dates,
// six rows of seven, starting at the week start on or before the 1st, UTC
// throughout. jstest/specs/calendar.spec.ts tests that the two agree.
function monthGrid(year, month, weekStartsOn) {
  const first = new Date(Date.UTC(year, month, 1));
  const offset = (first.getUTCDay() - weekStartsOn + 7) % 7;
  const grid = [];
  for (let i = 0; i < 42; i++) {
    grid.push(new Date(Date.UTC(year, month, 1 - offset + i)));
  }
  return grid;
}

function iso(date) {
  return date.toISOString().slice(0, 10);
}

function parseISO(value) {
  if (!value) return null;
  const [y, m, d] = value.split("-").map(Number);
  if (!y || !m || !d) return null;
  const date = new Date(Date.UTC(y, m - 1, d));
  return date.getUTCFullYear() === y && date.getUTCMonth() === m - 1 && date.getUTCDate() === d
    ? date
    : null;
}
```

- [ ] **Step 4: Implement selection**

**Known risks, flagged rather than hidden:**

1. **Task 0 decides `<table>` vs divs**, and Tasks 1–3's tests assert
   `role="row"` / `role="gridcell"` counts. If the source map lands on a real
   `<table>`, those roles are implicit and the assertions need to target
   `<tr>`/`<td>` instead. The counts (7 rows, 42 cells, 7 columnheaders) hold
   either way — adjust the selectors, not the numbers.
2. **Task 4 Step 3 extends the harness** with a `month` query parameter. That
   is the one place this plan modifies Phase 1's test infrastructure. Keep it
   generic; a component name hard-coded into the harness would be a defect.
3. **The `data-range-middle` assertion in Task 5's hover test** uses
   `toHaveAttribute(name, "")` for a valueless attribute. If Playwright's
   matcher does not treat a bare attribute as an empty string, use
   `expect(locator).toHaveAttribute(name)` or an `evaluate` check —
   verify the form against the first such assertion rather than assuming.
