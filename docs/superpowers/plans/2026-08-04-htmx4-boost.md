# htmx 4 Boosted Site Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Site-wide boosted navigation with idiomorph body morphs so docs-sidebar scroll (and other live UI state) survives page navigation.

**Architecture:** `htmx.org@4.0.0-beta6` (exact pin) is imported by the site entry (`web/main.js`) and by the Playwright harness's mirror entry (`jstest/harness-site.js`, bare specifier resolved via the harness import map). `siteLayout`'s `<body>` carries `hx-boost:inherited="true"` + `hx-swap="outerMorph"`. A small site-JS listener syncs `document.title` if beta6's boost doesn't. Library code (`ui/`, vendored files, CLI) is untouched.

**Tech Stack:** htmx 4.0.0-beta6 (core idiomorph), gsx site pages, Vite (site build), Playwright harness (jstest).

## Global Constraints

- Dependency is `htmx.org@4.0.0-beta6` with an **exact pin** (no `^`/`~`) in the repo-root package.json.
- Site only: no changes under `ui/`, `registry/`, `internal/cli`, or anything `gsxui add`/`init` vendors.
- The ⌘K palette keeps `window.location.assign` (ui/command.js is library code).
- htmx 4 beta API facts must be verified against https://four.htmx.org/docs (and /reference/attributes/hx-boost, /reference/attributes/hx-swap) before use — where this plan says "verify", read the doc page and adapt names; do not guess silently.
- gsx markup comments use `{/* */}`, never `//`. After editing any `.gsx`, run `go tool gsx generate`.
- `jstest/harness-site.js` must keep mirroring `web/main.js` (harness_test.go asserts the relationship); change both together.
- Playwright must run as `npx playwright test --config jstest/playwright.config.ts`. Known parallel-load flakes: dialog.spec.ts:453/503 — retry in isolation before blaming a change.

- [ ] **Step 1: Extend the spec with the real behavior (failing first)**

Append to `jstest/specs/site-boost.spec.ts` inside the describe block:

```ts
  test("sidebar scroll survives boosted navigation", async ({ page }) => {
    await page.goto("/components/button");
    const sidebar = page.locator("aside nav").first();
    // Scroll the docs sidebar container to its bottom. The scrollable
    // element is the aside's overflow container; adjust the locator to the
    // actual scrolling element (inspect site/pages/layout.gsx: the left
    // column) and note it in your report.
    const scrolled = await sidebar.evaluate((el) => {
      const scroller = el.closest("[class*='overflow-y']") ?? el;
      scroller.scrollTop = scroller.scrollHeight;
      return scroller.scrollTop;
    });
    expect(scrolled).toBeGreaterThan(0);

    await page.getByRole("link", { name: "Tooltip", exact: true }).click();
    await expect(page).toHaveURL(/\/components\/tooltip$/);
    await expect(page.locator("h1")).toHaveText(/tooltip/i);

    const after = await sidebar.evaluate((el) => {
      const scroller = el.closest("[class*='overflow-y']") ?? el;
      return scroller.scrollTop;
    });
    expect(after).toBe(scrolled);
  });

  test("document title updates on boosted navigation", async ({ page }) => {
    await page.goto("/components/button");
    await page.getByRole("link", { name: "Theming", exact: true }).first().click();
    await expect(page).toHaveURL(/\/docs\/theming$/);
    await expect(page).toHaveTitle(/Theming · gsxui/);
  });

  test("theme class survives boosted navigation", async ({ page }) => {
    await page.goto("/components/button");
    await page.locator("[data-site-theme-toggle]").click();
    const dark = await page.evaluate(() => document.documentElement.classList.contains("dark"));
    await page.getByRole("link", { name: "Theming", exact: true }).first().click();
    await expect(page).toHaveURL(/\/docs\/theming$/);
    expect(await page.evaluate(() => document.documentElement.classList.contains("dark"))).toBe(dark);
  });
```

Adjust locators to the real DOM (sidebar scroller, theme toggle selector — grep web/site.js for `data-site-theme-toggle`) and record any adjustment in your report. The assertions themselves (scroll preserved, URL+h1 changed, title synced, theme stable) are the requirements and must stay.

If "document title updates" fails (beta6 boost not syncing `<title>`): add to `web/site.js` (and it alone — harness-site.js imports site.js so both get it):

```js
// htmx 4 boosted navigation morphs the body; the <title> lives outside the
// swap, so mirror it from the incoming document ourselves.
document.addEventListener("htmx:afterSwap", (event) => {
  const title = event.detail?.response?.match?.(/<title>([^<]*)<\/title>/)?.[1];
  if (title) document.title = title;
});
```

Verify the actual v4 event name and detail shape at https://four.htmx.org/reference/events (v2's `htmx:afterSwap` detail differs; v4 may expose the response text under another key — adapt and note it). If v4 already syncs the title, skip this step entirely and note that.
